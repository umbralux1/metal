# План реализации (Implementation Plan): Корзина и оформление заказа

**Ветка (Branch)**: `002-cart-checkout` | **Дата (Date)**: 2026-10-27 | **Спецификация (Spec)**: [spec.md](spec.md)

## Кратко (Summary)

Обратная спецификация корзины плюс исправления, найденные при сверке: BUG-009…014 и две доработки (телефон без
кода страны, количество на странице «Заказ принят»). Новых таблиц и адресов нет. Существующие тесты получают ссылки
`002:FR-###`, непокрытые требования — охранные тесты.

## Технический контекст (Technical Context)

**Язык и версия**: Python 3.11 · **Зависимости**: без новых · **Хранение**: без изменений схемы; в снимке заказа
(`leads.calc`) новое поле `distance_km` для доставки · **Тесты**: pytest + httpx (ASGI)

**Затронутые модули**: `app/cart` (store, router, service, checkout, шаблоны), `app/leads/phone.py`,
`app/admin/leads.py` (строка доставки)

## Решения

| Что | Как |
|---|---|
| BUG-009 склейка резки | `store.add`: та же позиция с той же резкой (товар, единица, длина отрезка) — складывается число отрезков |
| BUG-010 ошибка без JavaScript | Ошибка расчёта — возврат на карточку с введёнными параметрами в адресе (`?unit=…&qty=…#calc`): карточка сама покажет ошибку калькулятора. Ошибки корзины (30 позиций, слишком много после склейки) — переход в корзину с кодом `?error=full` / `?error=too_much`; текст — из словаря в `app/cart`, не из адреса |
| BUG-011 склейка сверх предела | После `store.add` склеенная позиция пересчитывается калькулятором; ошибка — корзина не сохраняется |
| BUG-012 номер «-1» | `cart_update` / `cart_remove`: номер вне `0…len-1` — корзина не меняется |
| BUG-013 расстояние | `order_snapshot`: `distance_km` в снимке для любой доставки; админка и «Заказ принят» показывают км без машины |
| BUG-014 форма у снятого товара | `CartLineView.available`; форма количества — только у продающегося товара без резки |
| Телефон | `normalize_phone`: любые 10 цифр → +7 |
| «Заказ принят» | Позиции: штуки, метры, резка и сумма — из снимка заказа |
