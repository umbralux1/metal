# План реализации (Implementation Plan): Ограничение входа в админку

**Ветка (Branch)**: `003-admin-login-limit` | **Дата (Date)**: 2026-10-29 | **Спецификация (Spec)**: [spec.md](spec.md)

**Вход (Input)**: спецификация `specs/003-admin-login-limit/spec.md`

## Кратко (Summary)

Счёт неудачных входов переезжает из памяти процесса (`_failures` в `app/admin/auth.py`) в новую таблицу
`admin_login_failures`: отпечаток адреса и время. Проверка, запись ошибки и удаление старых записей — в одной
транзакции под блокировкой по отпечатку, как у заявок (001). Заблокированный адрес получает страницу входа
с сообщением «Слишком много попыток, попробуйте через 15 минут» и код 429; блокировка — предупреждение в журнале
с отпечатком.

## Технический контекст (Technical Context)

**Язык и версия (Language/Version)**: Python 3.11

**Основные зависимости (Primary Dependencies)**: FastAPI, SQLAdmin 0.32, SQLAlchemy async, Alembic. Новых нет.

**Хранение (Storage)**: PostgreSQL, новая таблица `admin_login_failures` (data-model.md)

**Тесты (Testing)**: pytest + httpx (ASGI) с адресом клиента на тест (`ASGITransport(client=(ip, port))`,
как `tests/test_lead_limit.py`). Браузерные не нужны: сообщение — уже существующий блок ошибки страницы входа SQLAdmin.

**Платформа (Target Platform)**: Linux; Render — на время разработки, рабочий сайт — российский дата-центр;
одна или несколько копий сайта

**Тип проекта (Project Type)**: веб-сайт с серверным рендерингом и админкой

**Затронутые модули (Modules)**: `app/admin` (основное), `app/core` (настройки), `app/models.py`, миграции

**Ограничения (Constraints)**: +3–4 запроса к базе на попытку входа (блокировка, удаление старых, счёт,
запись/обнуление) — по индексам, незаметно; вход — редкая операция.

**Решение по структуре (Structure Decision)**: ограничение — правило входа в админку, поэтому таблица и логика
в `app/admin`. Модуль маленький: `models.py` + логика в уже существующем `auth.py` (принцип VII — без `service.py`
на вырост).

**Существующие тесты**: фикстура `admin` в `conftest.py` входит с адреса по умолчанию и звала `reset_login_limits()`.
Удачный вход сам обнуляет счёт адреса (FR-004), а тесты блокировки идут с отдельных адресов — сброс не нужен.
