# Металлобаза — интернет-магазин металлопроката

FastAPI + PostgreSQL 16, серверный рендеринг (Jinja2), SEO-каталог с посадочными страницами по типоразмерам.

## Запуск

Нужны Python 3.11+ и Docker Desktop (или OrbStack).

```bash
cp .env.example .env
docker compose up -d                     # PostgreSQL 16 на localhost:5433 + база metal_test для тестов
source venv/bin/activate
pip install -r requirements-dev.txt
alembic upgrade head                     # создать таблицы
python -m app.catalog.seed               # демо-данные: арматура и профильная труба
python main.py                           # http://127.0.0.1:8000
pytest                                   # тесты, в т. ч. SEO-контракт
```

Документация API (`/docs`) включается только при `DEBUG=true`.

## Админка

`/admin` — разделы, товары, цены, посадочные (SEO-фильтры), редиректы и заявки. Работает на SQLAdmin.

- Включается паролем: `ADMIN_PASSWORD` в `.env` (локально) или в `deploy/render.env` / Environment на Render. Без пароля `/admin` не существует.
- Логин — `ADMIN_USERNAME` (по умолчанию `admin`). После 5 неверных паролей за 15 минут вход с этого IP закрывается.
- `SECRET_KEY` подписывает сессию. Если не задан, генерируется при запуске, и после рестарта придётся войти заново.
  Для теста на Render он лежит в `deploy/render.env`.

Что админка делает сама:
- **Адреса.** Slug можно не заполнять — он соберётся из названия латиницей; путь строится от родительского раздела.
  Адрес не может совпасть с уже существующей страницей.
- **Редиректы.** Сменили slug или перенесли раздел — у всех вложенных разделов, посадочных и товаров меняются адреса,
  а со старых ставятся 301. Цепочки схлопываются, петли удаляются. Удалённая посадочная перенаправляет в свой раздел.
- **Выключение вместо удаления.** Разделы и товары не удаляются: снимите «Активен», и адрес начнёт отдавать 301
  на ближайший активный раздел выше. Так проиндексированные ссылки не превращаются в 404.
- **Поиск.** Поисковый текст товара пересчитывается при каждом сохранении.
- **Цены** — отдельный раздел, вводятся в копейках (4325 = 43,25 ₽). Меню разделов на сайте обновляется в течение минуты.

Интерфейс кнопок SQLAdmin на английском; поля и разделы подписаны по-русски.

## Посадочные «по размеру»

Страницы вида «Арматура 12 мм» и «Труба профильная 40х20» создаёт генератор `app/catalog/landings.py`
по правилам из `app/catalog/landing_rules.py` (раздел → по каким размерам делать страницы).

- Страница появляется под каждый размер, который есть в товарах, если товаров на ней хотя бы 2
  (`MIN_PRODUCTS`). Размер с одним товаром закрывает страница самого товара — вторая страница с тем же
  содержимым конкурировала бы с ней в выдаче.
- Посадочная кладётся в самый глубокий раздел, где лежат все её товары: «Арматура 12 мм» (А500С + А1) —
  в «Арматуру», «Труба 40х40» (только квадратные) — в «Трубу квадратную».
- Title, description, H1 и текст собираются из данных товаров: марки стали, стандарт, длины, толщины стенки,
  вес метра и метров в тонне. `{price}` в title и description подставляет актуальную минимальную цену.
- Генератор запускается при каждом старте на хостинге (`AUTO_LANDINGS=true`), вручную —
  `python -m app.catalog.landings` или в админке: «Посадочные» → Actions → «Обновить посадочные из каталога».
- Размер пропал из каталога — страница не удаляется, а получает noindex и уходит из sitemap; вернулся — снова в индексе.
- Посадочную, поправленную в админке, генератор больше не трогает (колонка «Авто» гаснет).
  Ручные посадочные можно создавать как раньше.

**Адреса товаров.** Товар с размером лежит внутри посадочной своего размера:
`/catalog/truba-profilnaya/kvadratnaya/40x40/40x40x2/`, `/catalog/armatura/12-mm/12-mm-a500s/`.
Slug товара — название без названия раздела. Посадочная, в которой один товар, тоже создаётся (как родитель адреса),
но закрыта от индекса. Адреса ведёт генератор: товар сменил размер, раздел переименовали — адрес пересчитывается,
со старого ставится 301. Slug, заданный в админке руками, генератор не трогает. Раздел товара определяется
по полю «Раздел», а не по адресу: подраздел «Арматура А500С» показывает свои товары, хотя их адреса в «12-mm».

**Карточка товара.** Title: «Труба профильная квадратная 20х20х2 купить в Москве — цена 98 ₽/м» (уточнение
подраздела — `qualifiers` в правиле). В карточке — цена за штуку стандартной длины, текст из данных товара
(вес, метров в тонне, вес штуки, где применяют), «другие варианты» этого размера и соседние размеры.

Чтобы добавить раздел, допишите правило в `RULES` с адресом раздела (например, `"ugolok"`) и полями размера.

## Деплой на Render

В репозитории лежит Blueprint `render.yaml`: по нему Render создаёт веб-сервис и базу PostgreSQL 16.

### Тестовые переменные: `deploy/render.env`

Все настройки тестового стенда (данные магазина, `ALLOW_INDEXING=false`, `SEED_DEMO=true`, логин и пароль админки,
`SECRET_KEY`) лежат в `deploy/render.env` и хранятся в git. Приложение читает этот файл само, но только на Render
(там есть переменная `RENDER`); локально он не используется. В панели Render нужен только `DATABASE_URL`.

Порядок важности: Environment в панели Render > `deploy/render.env` > значения в коде. Поэтому любую настройку можно
переопределить в панели, не меняя файл.

> В файле пароль админки открытым текстом. Держите репозиторий приватным. Перед настоящим запуском задайте
> `ADMIN_PASSWORD` и `SECRET_KEY` в панели Render и уберите их из файла.

1. Залейте проект на GitHub (или GitLab): `git remote add origin …` и `git push -u origin main`.
2. На [dashboard.render.com](https://dashboard.render.com): **New → Blueprint**, выберите репозиторий, нажмите **Apply**.
3. Через пару минут сайт откроется по адресу вида `https://metal-web.onrender.com`.

При каждом запуске `python main.py` (его вызывает `scripts/render-start.sh`) применяет миграции,
при `SEED_DEMO=true` загружает демо-товары и запускает uvicorn на `0.0.0.0:$PORT`. Каждый push в `main` деплоится автоматически.

Пока сайт живёт на `*.onrender.com`, он закрыт от поисковиков (`ALLOW_INDEXING=false`): robots.txt запрещает
всё, а каждый ответ получает `X-Robots-Tag: noindex`. Это нужно, чтобы тестовая копия не попала в индекс
раньше основного домена. Когда подключите свой домен (Settings → Custom Domains), поменяйте в Environment (или в `deploy/render.env`):
`SITE_URL=https://ваш-домен.ru`, `ALLOW_INDEXING=true`, `SEED_DEMO=false`.

### Если сервис создан вручную (New → Web Service)

1. Сначала создайте базу: **New → Postgres**, регион тот же, что у сервиса. Скопируйте **Internal Database URL**.
2. В настройках веб-сервиса:
   - **Build Command:** `pip install -r requirements.txt`
   - **Start Command:** `python main.py` — на хостинге он сам применит миграции и запустит сервер на `0.0.0.0:$PORT`
   - **Health Check Path:** `/health`
3. **Environment:** только `DATABASE_URL` = Internal Database URL из шага 1. Остальное берётся из `deploy/render.env`.

Без `DATABASE_URL` приложение на Render сразу остановится с подсказкой, что переменная не задана.

Ограничения бесплатного тарифа Render ([подробнее](https://render.com/docs/free)):
- веб-сервис засыпает после 15 минут без запросов, первый запрос после сна идёт медленно;
- бесплатная база PostgreSQL удаляется через 30 дней после создания.

Для настоящего запуска поменяйте в `render.yaml` `plan: free` на платные планы: веб-сервис — `0.5c-512mb` или выше,
база — `0.1c-256mb` или выше. Адрес базы Render отдаёт в виде `postgresql://…`, приложение само переключает его
на драйвер psycopg; `SITE_URL` без явного значения берётся из `RENDER_EXTERNAL_URL`.

## Как устроен каталог

Один роут `/catalog/{path}/` ищет по пути сначала раздел (`Category`), потом SEO-страницу фильтра
(`FilterLanding`), потом товар (`Product`). Не нашёл — 404, но сначала проверяется таблица `redirects`.

- **Раздел** показывает товары своих подразделов (по префиксу пути) и ссылки на посадочные «по размеру».
- **FilterLanding** = раздел + фильтр в JSON: `{"diameter_mm": 12}` или `{"width_mm": 40, "height_mm": 40}`;
  список значений даёт условие IN. Допустимые ключи — `FILTERABLE_COLUMNS` в `repository.py`.
  `is_indexable=false` — страница работает, но получает `noindex` и не попадает в sitemap.
- **Цены** хранятся в копейках (`Price.amount_kop`) отдельно по единицам: метр, тонна, штука.
  «От N ₽» в title считается по базовой единице товара.
- **Мета-теги**: если в записи заполнены `title`, `description`, `h1` — берутся они, иначе шаблон из `seo/meta.py`.

## Калькулятор и заявки

На карточке товара — расчёт заказа: количество в штуках, метрах или килограммах, резка в размер.
Логика — чистые функции в `app/catalog/calculator.py`, деньги в копейках.

- Без резки количество округляется до целых прутков (длина из `Product.length_m`).
- С резкой считается раскрой: сколько прутков нужно, сколько резов и сколько остаётся в обрезках.
  Если отрезки делят пруток без остатка, последний отрезок получается без реза.
- От `TON_PRICE_FROM_KG` (по умолчанию 1000 кг) действует цена за тонну, если она есть.
- Пересчёт на лету: `static/js/calc.js` запрашивает `/api/calc/{id}/` и подставляет кусок HTML.
  Без JavaScript форма работает обычным GET на страницу товара (такие адреса получают `noindex`).
- Заявка (`POST /api/lead/`) пересчитывается на сервере, сохраняется в таблицу `leads` со снимком расчёта
  и пишется в лог `metal.leads`. Отправку в Telegram или на почту подключать в `app/leads/notify.py`.
- Защита от ботов — скрытое поле-ловушка `website`. Телефон приводится к виду `+7XXXXXXXXXX`.

Настройки: `CUT_PRICE_KOP` (цена реза в копейках, по умолчанию 5000 = 50 ₽), `TON_PRICE_FROM_KG`.

## Внешний вид

- Шрифт Golos Text (OFL) лежит локально: `app/static/fonts/golos-text.woff`, кириллица и латиница, все веса в одном файле.
- Цвета и размеры — CSS-переменные в начале `app/static/css/main.css`.
- Фирменный элемент — чертёж сечения (`app/catalog/drawings.py`): строится из размеров товара,
  со штриховкой разреза и размерными линиями. Профиль угадывается по полям или задаётся в `attrs["profile"]`
  (`rebar`, `round`, `tube_rect`, `plate`). Значки разделов — там же, по slug корневого раздела.
- На телефоне таблица товаров превращается в карточки, внизу экрана — панель «Позвонить / мессенджер / Каталог».
- Поиск `/search/?q=` ищет по `search_text` (все слова запроса), сортирует по похожести через pg_trgm; страница закрыта от индексации.

## SEO-правила, которые держат тесты

- каждая страница из sitemap отдаёт 200, один H1, canonical на себя, без noindex;
- `?sort=…`, любые параметры и страницы пагинации 2+ — `noindex, follow`, canonical на чистый адрес;
- `/Catalog/Armatura`, `/catalog/armatura`, `/catalog//armatura/` → 301 на `/catalog/armatura/`;
- закрытые комбинации фильтров не попадают в sitemap.
