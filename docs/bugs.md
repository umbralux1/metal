# Ошибки и регрессионные тесты

Журнал найденных ошибок. У каждой — номер `BUG-NNN` и регрессионный тест с этим номером в описании
(`"""BUG-001: …"""`): `grep -rn BUG-001` находит и запись, и тест. Тест не удаляют и не ослабляют — он не даёт
ошибке вернуться. Порядок работы — в `CLAUDE.md`, раздел «Ошибки».

Статусы: **открыта** → **в работе** (тест написан и падает) → **исправлена** (коммит сделан).

Шаблон записи:

```
## BUG-NNN: коротко, что не так
- **Статус:** открыта
- **Найдена:** дата, кем или чем (владелец на сайте, mypy, тест)
- **Что видно:** что делал и что получил вместо ожидаемого
- **Как воспроизвести:** браузер и ширина окна, адрес, действия по шагам
- **Причина:** — (после разбора)
- **Исправление:** — (коммит `fix: … (BUG-NNN)`)
- **Регрессионный тест:** — (файл::тест)
```

Снимки экрана к ошибкам — в `docs/bugs/`, имя начинается с номера: `BUG-004-safari.png`.

## BUG-014: у снятого с продажи товара в корзине остаётся поле количества
- **Статус:** исправлена
- **Найдена:** 27.10.2026, агент при сверке спецификации корзины (specs/002-cart-checkout), подтвердил владелец
- **Что видно:** товар в корзине сняли с продажи — у позиции сообщение «Товар больше не продаётся — удалите его из корзины», но поле количества и «Пересчитать» на месте.
- **Как воспроизвести:** положить арматуру в корзину → в админке снять у товара «Активен» → обновить `/cart/`.
- **Спецификация:** код не выполняет `002:FR-006` — у снятого товара только сообщение и удаление.
- **Причина:** `app/templates/cart/page.html`: форма количества показывается, если товар есть в базе, без проверки, продаётся ли он.
- **Исправление:** коммит `fix: cart … (BUG-009…014)` — `CartLineView.available` (`app/cart/service.py`): поле количества — только у продающегося товара без резки.
- **Регрессионный тест:** `tests/test_cart_bugs.py::test_retired_product_has_no_quantity_form`

## BUG-012: номер позиции «-1» меняет или удаляет последнюю позицию корзины
- **Статус:** исправлена
- **Найдена:** 27.10.2026, агент при сверке спецификации корзины (specs/002-cart-checkout), подтвердил владелец
- **Что видно:** запрос на удаление (или изменение) с номером позиции -1 удаляет последнюю позицию, хотя такой позиции нет.
- **Как воспроизвести:** два товара в корзине → на `/cart/` в консоли браузера: `fetch('/cart/remove/', {method: 'POST', body: new URLSearchParams({index: '-1'})}).then(() => location.reload())` — удалена последняя позиция.
- **Спецификация:** код не выполняет `002:FR-007` — позиция, которой нет, корзину не меняет.
- **Причина:** `app/cart/router.py`, `cart_update` и `cart_remove`: отрицательный номер в Python считается с конца списка.
- **Исправление:** коммит `fix: cart … (BUG-009…014)` — `app/cart/router.py`, `_index`: номер вне 0…N-1 — корзина не меняется.
- **Регрессионный тест:** `tests/test_cart_bugs.py::test_negative_index_does_not_change_cart`

## BUG-009: одинаковая резка, добавленная в корзину второй раз, ложится отдельной строкой
- **Статус:** исправлена
- **Найдена:** 27.10.2026, агент при сверке спецификации корзины (specs/002-cart-checkout), подтвердил владелец
- **Что видно:** арматура с резкой 10 × 3,9 м, добавленная в корзину дважды, — две одинаковые строки вместо одной
  20 × 3,9 м. Без резки тот же товар склеивается (11,7 м + 11,7 м = 23,4 м).
- **Как воспроизвести:** `/catalog/armatura/12-mm/12-mm-a500s/` → «Резать в размер», длина 3,9, отрезков 10 →
  «В корзину» дважды → `/cart/`: две строки «резка 10 × 3,9 м».
- **Спецификация:** код не выполняет `002:FR-003` — одинаковая резка (товар, длина отрезка) складывается по числу
  отрезков, разная — отдельные строки.
- **Причина:** `app/cart/store.py`, `add`: склейка только для позиций без резки (`and not item.cut`).
- **Исправление:** коммит `fix: cart … (BUG-009…014)` — `app/cart/store.py`: `add` склеивает и позиции с резкой — та же длина отрезка («3,9» = «3.9») складывает число отрезков; `same_as` сравнивает длину как число.

## BUG-008: тот же товар, добавленный в корзину второй раз, ложится отдельной строкой, если в количестве пробел
- **Статус:** исправлена
- **Найдена:** 26.10.2026, агент при разборе дублей разбора чисел
- **Что видно:** количество «1 000» калькулятор принимает (пробелы между разрядами убирает), позиция попадает
  в корзину. Тот же товар с тем же количеством ещё раз — в корзине две одинаковые строки вместо одной на 2000.
- **Как воспроизвести:** любой браузер, карточка товара, количество «1 000», «В корзину» два раза, открыть корзину.
- **Причина:** `cart/store.add` складывает количества своим разбором (`Decimal(qty.replace(",", "."))`), который
  пробелы не убирает, в отличие от калькулятора. На «1 000» — ошибка разбора, и функция молча добавляет новую строку.
  Одна из пяти копий разбора чисел (`docs/tech-debt.md`).
- **Исправление:** коммит `refactor: one place for number formatting and parsing (BUG-008)` — корзина складывает
  количества общим `parse_decimal` (`app/core/numbers.py`), как и калькулятор.
- **Регрессионный тест:** `tests/test_numbers.py::test_same_item_with_spaced_quantity_merges_in_cart`

## BUG-005: подсказки поиска слишком узкие, товары не отличить

## BUG-004: клик по строке в таблице товаров всегда открывает последний товар
- **Статус:** исправлена
- **Найдена:** 23.10.2026, владелец на локальном сайте
- **Что видно:** в результатах поиска «Арматура 12» строка «Арматура 12 мм А500С» (последняя) всё время подсвечена,
  клик в любое место строки «А1» или «А400» открывает А500С. Другие товары не открыть. С открытой консолью
  разработчика (окно ниже) ошибка пропадает. Та же таблица — на страницах разделов каталога.
- **Снимок экрана:** [bugs/BUG-004-safari.png](bugs/BUG-004-safari.png) — строка А500С подсвечена, хотя курсор не на ней.
- **Как воспроизвести:** Safari 26.6 на компьютере (macOS), окно во весь экран (ширина 1728 px),
  http://127.0.0.1:8000/search/?q=Арматура+12, кликнуть по строке А400. В Google Chrome, Chromium и WebKit
  из Playwright не воспроизводится.
- **Причина:** строка кликается целиком за счёт ссылки, растянутой слоем `.p-name a::after { position: absolute;
  inset: 0 }` до ближайшего предка с `position`. Им должна быть строка (`.products tbody tr { position: relative }`),
  но Safari 26.6 не применяет `position` к строке таблицы (вычисленное значение — `static`, проверено в консоли).
  Тогда слой растягивается на всё окно, сверху — слой последней строки. С открытой консолью окно ниже и
  до таблицы не достаёт.
- **Исправление:** коммит `fix: product table rows clickable in Safari (BUG-004)`. На экранах шире 640 px строки
  таблицы — сетка (`display: grid`) с одинаковыми колонками у шапки и строк, как карточки на телефоне. Сетка —
  граница для растянутой ссылки в любом браузере. HTML не менялся, ссылка в строке одна. Вид на 1280 px прежний,
  на 360 px совпал пиксель в пиксель.
- **Регрессионный тест:** `tests/test_browser_product_rows.py::test_click_anywhere_in_row_opens_that_product` —
  строкам, которые браузер показывает как `table-row`, задаётся `position: static`, как в Safari 26.6; клик
  по цене в каждой строке должен открыть свой товар. На старом CSS тест падает, на новом проходит.
