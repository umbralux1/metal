# База данных

PostgreSQL 16 с расширением `pg_trgm` (быстрый поиск по части слова). Схему ведёт Alembic
(`migrations/versions/`), миграции применяются автоматически при запуске (`app/bootstrap.py`).

Корзина в базе не хранится: она лежит в подписанной cookie посетителя и превращается в запись `leads`
только при оформлении.

## Схема

```
categories ─┬─< categories        (parent_id: дерево разделов)
            ├─< products ──< prices
            │        └──< leads   (product_id, может быть пустым)
            └─< filter_landings

redirects                          (отдельно, без связей)
delivery_vehicles                  (отдельно: машины и тарифы доставки)
admin_login_failures               (отдельно: неудачные входы в админку)
alembic_version                    (служебная, номер последней миграции)
```

`─<` — «один ко многим»: у раздела много товаров, у товара несколько цен.

## Общие поля

Есть почти во всех таблицах:

| Поле | Тип | Что это |
|---|---|---|
| `id` | integer | Первичный ключ |
| `created_at` | timestamptz | Когда создана запись (ставит база) |
| `updated_at` | timestamptz | Когда изменена последний раз |

SEO-поля есть у `categories`, `products` и `filter_landings`. Пустое поле значит «собрать по шаблону»
из `app/catalog/seo.py`:

| Поле | Тип | Что это |
|---|---|---|
| `title` | varchar(255) | `<title>` страницы. `{price}` в посадочных подставит «от N ₽» |
| `description` | varchar(500) | meta description |
| `h1` | varchar(255) | Заголовок на странице. Пусто — название |
| `seo_text` | text | HTML-текст внизу страницы |

## Адреса: `slug` и `path`

У раздела, товара и посадочной два поля адреса:

- `slug` — последняя часть адреса латиницей: `a500c`, `12-mm`, `20x20x2`.
- `path` — полный путь без `/catalog/`: `armatura/a500c`. По нему сайт находит страницу,
  поэтому `path` уникален внутри каждой таблицы.

Адрес на сайте — `/catalog/{path}/`. Оба поля админка заполняет сама. Если адрес меняется, старый
записывается в `redirects`.

## `categories` — разделы каталога

Дерево любой глубины: «Арматура → А500С», «Труба профильная → Квадратная».

| Поле | Тип | Что это |
|---|---|---|
| `parent_id` | → `categories.id` | Родительский раздел. Пусто — корневой раздел (в меню каталога) |
| `slug` | varchar(120) | Часть адреса. Уникален среди детей одного родителя |
| `path` | varchar(500), уникален | `truba-profilnaya/kvadratnaya` |
| `name` | varchar(255) | Название: «Квадратная» |
| `sort` | integer | Порядок в меню, меньше — выше |
| `is_active` | boolean | Выключенный раздел не виден вместе со всем, что внутри (подразделы, товары, посадочные), — проверка `visible_category()` в `app/catalog/repository.py`. Адреса отдают 301 на видимый раздел выше. Скрытые на запуске разделы выключила миграция `0006` |
| + SEO-поля | | |

Раздел нельзя удалить, пока в нём есть товары или подразделы (`ON DELETE RESTRICT`).

## `products` — товары

Одна позиция проката: «Арматура 12 мм А500С», «Труба профильная 40х20х2».

| Поле | Тип | Что это |
|---|---|---|
| `category_id` | → `categories.id` | Раздел. Именно он, а не адрес, определяет, где товар в каталоге |
| `slug` | varchar(160) | `20x20x2` |
| `path` | varchar(500), уникален | `truba-profilnaya/kvadratnaya/20x20/20x20x2`. Товар с размером лежит внутри посадочной |
| `name` | varchar(255) | Название |
| `sku` | varchar(64), уникален | Артикул, можно не заполнять |
| `steel_grade` | varchar(64) | Марка стали или класс: `Ст3сп`, `А500С` |
| `gost` | varchar(64) | `ГОСТ 8639-82` |
| `diameter_mm` | numeric(8,2) | Диаметр: арматура, круг, труба, свая |
| `width_mm` | numeric(8,2) | Ширина: профильная труба, уголок, полоса, квадрат |
| `height_mm` | numeric(8,2) | Высота: профильная труба, уголок |
| `thickness_mm` | numeric(8,2) | Толщина листа или стенки |
| `length_m` | numeric(8,3) | Длина прутка или трубы. Нужна калькулятору для расчёта резки |
| `weight_per_m_kg` | numeric(10,4) | Вес одного метра, кг. Для пересчёта в тонны |
| `weight_per_piece_kg` | numeric(10,3), > 0 | Вес одной штуки, кг — у штучных товаров (лист, свая). Для подбора машины доставки. Пусто — неизвестен |
| `piece_length_m` | numeric(6,3), > 0 | Длина одной штуки (самая длинная сторона листа), м. Для подбора машины. Пусто — неизвестна |
| `base_unit` | varchar(8) | Основная единица продажи: `m`, `t`, `pcs`, `m2`. В ней цена «от» |
| `in_stock` | boolean | В наличии |
| `is_active` | boolean | Выключенный товар не виден, адрес отдаёт 301 в раздел |
| `search_text` | text | Текст для поиска (название + артикул + марка + ГОСТ). Пересчитывается при сохранении |
| `attrs` | jsonb | Доп. свойства, например `{"profile": "angle"}` — какой чертёж сечения рисовать |
| + SEO-поля | | |

Из полей размеров (`diameter_mm`, `width_mm`, `height_mm`, `thickness_mm`) собираются посадочные
«по размеру» (см. `filter_landings`).

Индексы: `category_id`, `diameter_mm`, `steel_grade` и триграммный GIN по `search_text` для поиска.

## `prices` — цены

| Поле | Тип | Что это |
|---|---|---|
| `product_id` | → `products.id` | Товар. Удалили товар — удалятся и его цены (`CASCADE`) |
| `unit` | varchar(8) | Единица: `m` метр, `t` тонна, `pcs` штука, `m2` квадратный метр |
| `amount_kop` | integer | Цена **в копейках**: `4325` = 43,25 ₽, `4870000` = 48 700 ₽ |

У товара одна цена на каждую единицу (уникальная пара `product_id + unit`). Обычно две: за метр
и за тонну. В админке цены вводятся в рублях прямо в карточке товара.

**Почему отдельная таблица.** Цен у товара несколько, и набор единиц разный: арматура продаётся метрами
и тоннами, сваи штуками, лист квадратными метрами. Четыре колонки в `products` были бы в основном пустыми.
Отдельная таблица позволяет добавить новую единицу без миграции и одним запросом найти «цену от» по разделу.

**Почему копейки.** Целые числа считаются точно: 0,1 + 0,2 в дробях даёт 0,30000000000000004, а в копейках
10 + 20 = 30. Деньги во всём проекте (калькулятор, корзина, заявки) хранятся и считаются в копейках.

## `filter_landings` — посадочные «по размеру»

SEO-страницы под запросы вроде «арматура 12 мм» или «труба профильная 40х40»: раздел + фильтр по размеру.

| Поле | Тип | Что это |
|---|---|---|
| `category_id` | → `categories.id` | Раздел, внутри которого страница. Удалили раздел — удалятся посадочные |
| `slug` | varchar(160) | `12-mm`, `40x40` |
| `path` | varchar(500), уникален | `armatura/12-mm` |
| `name` | varchar(255) | «Арматура 12 мм» |
| `filters` | jsonb | Условие отбора товаров: `{"diameter_mm": 12}`, `{"width_mm": 40, "height_mm": 40}`. Список значений — «любое из» |
| `is_indexable` | boolean | Выключено — страница работает, но получает `noindex` и не попадает в sitemap |
| `sort` | integer | Порядок в списке размеров |
| `is_generated` | boolean | Создана автоматически. Генератор её обновляет; правка в админке снимает флаг |
| + SEO-поля | | |

Автоматические посадочные создаёт генератор (`app/catalog/landings.py`) по правилам из
`app/catalog/landing_rules.py`. Посадочная, на которую попало меньше 2 товаров, получает `noindex`:
она дублировала бы карточку единственного товара.

## `redirects` — перенаправления

| Поле | Тип | Что это |
|---|---|---|
| `from_path` | varchar(500), уникален | Старый адрес: `/catalog/old-armatura/` |
| `to_path` | varchar(500) | Новый адрес |
| `status_code` | integer | `301` навсегда (по умолчанию), `302` временно, `308` |

Сайт проверяет таблицу, когда страница не найдена. Записи появляются сами при смене адреса раздела,
товара или посадочной и при удалении посадочной. Цепочки (A→B→C) схлопываются в A→C, петли удаляются.

## `leads` — заявки и заказы

Заявка с карточки товара или заказ из корзины.

| Поле | Тип | Что это |
|---|---|---|
| `product_id` | → `products.id` | Товар заявки. У заказа из корзины пусто. Удалили товар — поле очистится, заявка останется |
| `product_name` | varchar(255) | Название товара на момент заявки, у заказа — «Корзина: 3 поз.» |
| `name` | varchar(120) | Имя клиента |
| `phone` | varchar(32) | Телефон в виде `+7XXXXXXXXXX` |
| `comment` | text | Комментарий клиента. У заказа впереди способ получения и адрес |
| `calc` | jsonb | Снимок расчёта на момент заявки (см. ниже) |
| `status` | varchar(20) | `new` новая, `in_progress` в работе, `done` выполнена, `spam` спам |
| `client_hash` | varchar(32) | Отпечаток адреса подключения (HMAC с `SECRET_KEY`) для счёта заявок: не больше 5 с адреса за 10 минут (specs/001-lead-rate-limit). Сам адрес не хранится. Индекс с `created_at` |

`calc` — снимок, а не ссылка на цены: цены потом меняются, а сумма в заявке должна остаться той,
которую видел клиент.

Заявка на один товар:

```json
{
  "unit": "m", "qty": "300", "cut": false,
  "meters": "300", "pieces": 25, "weight_kg": "266.4",
  "price_unit": "m", "price_kop": 4325, "material_kop": 1297500,
  "cuts": 0, "cut_kop": 0, "waste_m": "0",
  "total_kop": 1297500
}
```

Что внутри: что ввёл клиент (`unit`, `qty`, `cut`, `cut_len`, `cut_count`) и результат калькулятора —
метры, прутки, вес, по какой цене считали (`price_unit`, `price_kop`), стоимость металла, число и цена
резов, обрезки и итог `total_kop`.

Заказ из корзины — те же поля по каждой позиции плюс общие:

```json
{
  "kind": "cart",
  "items": [
    {"product_id": 12, "name": "Арматура 12 мм А500С", "url": "/catalog/armatura/12-mm/12-mm-a500s/",
     "meters": "300", "pieces": 25, "total_kop": 1297500, "...": "..."}
  ],
  "total_kop": 1297500,
  "delivery": "delivery",
  "address": "Москва, ул. Строителей, 5"
}
```

`delivery` — `delivery` (доставка, тогда заполнен `address`) или `pickup` (самовывоз).

С доставкой по машинам в заказе ещё `vehicle` (машина, км, цена доставки), `buyer` (частное лицо или организация
с ИНН), `payment` (`cash` или `invoice`), `goods_kop` и `delivery_kop`; `total_kop` — товары + доставка.
Подробно — [delivery.md](delivery.md#что-сохраняется-в-заявке).

## `delivery_vehicles` — машины доставки и тарифы

Какие машины возят заказы и сколько стоит доставка. Цена: базовая за первые `included_km` км,
дальше `price_per_km_kop` за каждый километр.

| Поле | Тип | Что это |
|---|---|---|
| `name` | varchar(120), уникален | «Грузовик до 5 т» |
| `max_weight_kg` | integer, > 0 | Грузоподъёмность, кг |
| `max_length_m` | numeric(5,2), > 0 | Самый длинный груз, который влезает, м (прутки 11,7 м — только длинномер) |
| `base_price_kop` | integer, ≥ 0 | Базовая цена **в копейках** |
| `included_km` | integer, ≥ 0 | Сколько километров входит в базовую цену |
| `price_per_km_kop` | integer, ≥ 0 | Цена каждого следующего километра, в копейках |
| `self_unloading` | boolean | Выгрузка силами покупателя (у манипулятора — нет, у него кран) |
| `sort` | integer | Порядок карточек, от маленькой машины к большой |
| `is_active` | boolean | Выключенная машина не предлагается покупателю |

Начальные тарифы кладёт `app/delivery/seed.py` при запуске сервера, **только в пустую таблицу**:
цены, поправленные вручную, и удалённые машины при перезапуске не возвращаются.

Подробно — формула цены, примеры, как менять тарифы: [delivery.md](delivery.md).

## `admin_login_failures` — неудачные входы в админку

Одна строка — один неверный пароль. По ним сайт закрывает вход с адреса после 5 ошибок за 15 минут
(`ADMIN_LOGIN_LIMIT`, `ADMIN_LOGIN_LIMIT_MINUTES`). Счёт общий для всех копий сайта и переживает перезапуск.

| Поле | Тип | Что это |
|---|---|---|
| `client_hash` | varchar(32) | Отпечаток адреса подключения (`client_fingerprint`); сам адрес, логин и пароль не хранятся |
| `created_at` | timestamptz | Когда была попытка, по часам базы |

Записи старше окна удаляются при каждой попытке входа; удачный вход удаляет записи своего адреса.
Подробно — [specs/003-admin-login-limit](../specs/003-admin-login-limit/spec.md).

## Полезные запросы

```sql
-- Товары раздела со всеми вложенными подразделами и ценой за метр в рублях
SELECT p.name, pr.amount_kop / 100.0 AS rub_per_m
FROM products p
JOIN categories c ON c.id = p.category_id
LEFT JOIN prices pr ON pr.product_id = p.id AND pr.unit = 'm'
WHERE c.path = 'armatura' OR c.path LIKE 'armatura/%'
ORDER BY p.name;

-- Товары без цены
SELECT p.id, p.name FROM products p
WHERE NOT EXISTS (SELECT 1 FROM prices pr WHERE pr.product_id = p.id);

-- Новые заявки с суммой
SELECT id, created_at, name, phone, product_name, (calc->>'total_kop')::int / 100.0 AS rub
FROM leads WHERE status = 'new' ORDER BY created_at DESC;

-- Посадочные, скрытые от поиска
SELECT path, name FROM filter_landings WHERE NOT is_indexable ORDER BY path;
```

Менять данные лучше через админку: при сохранении она пересчитывает адреса, редиректы, поисковый текст
и посадочные. Правка напрямую в базе этого не делает. После ручной правки товаров запустите генератор:
`python -m app.catalog.landings`.

## Как менять схему

1. Поменять модель в `app/catalog/models.py` или `app/leads/models.py`.
2. `alembic revision --autogenerate -m "что изменилось"` и проверить созданный файл в `migrations/versions/`.
3. `alembic upgrade head` локально. На Render миграция применится сама при следующем деплое.
